# Deploy to Render with Docker

1. Push this repository to GitHub and create a Render **Blueprint** from it.
   Render will use the root `Dockerfile` and `render.yaml`.
2. Create a Render PostgreSQL database in the same region as the web service.
   Set `DATABASE_URL` to that database's **internal connection string**.
3. Enter secure values for `GNANAVEL_INITIAL_PASSWORD` and
   `ADMIN_INITIAL_PASSWORD` when prompted. These values are used only when
   the corresponding accounts are first created. Existing accounts keep their
   current password.
4. `SECRET_KEY` is generated by Render. Set `GROQ_API_KEY` in the service
   environment to enable AI comment generation with Groq. The Blueprint selects
   Groq by default; `GROQ_MODEL` defaults to `llama-3.3-70b-versatile`. To use
   Gemini or OpenAI instead, change `MODEL_SELECTION` to `GEMINI` or `OPENAI`
   and provide the matching `GEMINI_API_KEY` or `OPENAI_API_KEY`.
5. Add `CLOUDINARY_URL` if profile photos should persist across deployments.

The database URL is required: Render's container filesystem is ephemeral, so
SQLite data stored inside the container would not persist across redeploys.
Profile photos stored only on local disk are also ephemeral; configure
Cloudinary for persistent photo storage.

The known demo student accounts and their sample student record are removed at
startup; other student accounts and records are left unchanged.

For a local Docker test, run:

```powershell
docker build -t mentor-dashboard .
docker run --rm -p 10000:10000 -e SECRET_KEY=local-test-secret -e DATABASE_URL=sqlite:////app/instance/local.db mentor-dashboard
```

Then open `http://localhost:10000`.
